# Web 控制台

[English](web.md)

控制台（`web/src`）用 [`web/ui`](../web/ui/README.md) 里的 `@olorinm/agent-ui` 组装页面（页面布局在 `./pages`，底层组件在 `.` 与 `./app`）。
组件包只接收数据、React 内容和回调，不依赖 Mau、Router、Host 或 Environment。认证、导航、接口请求和环境/渠道流程都在 `web/src`。

控制台提供与自有伙伴的对话（单聊和群聊）、伙伴创建与管理、环境生命周期、渠道连接、连接器账号和设置。
它只访问同域的 Mau（`/_mau/v1`）和内嵌的 Router（`/_agent-router/v1`）；浏览器不持有 Host 凭据，也不直连执行环境。
“新建应用”入口保留，明确显示“尚未接入”，没有对应后端。应用列表来自部署方提供的应用服务（`GET /_mau/v1/apps`，由 `createMau` 的 `dependencies.apps` 提供；没有时返回 `{ configured: false, data: [] }`）。最多三个应用可以固定在顶部导航里，这个选择保存在浏览器本地。详见英文文档的 [Apps](web.md#apps)。

`web/` 是 npm workspace，`web/package-lock.json` 同时锁定控制台与 `web/ui`；`npm run build:web` 先构建 `web/ui`。

## 开发

```sh
node scripts/bootstrap.mjs            # 同时安装 web/ 依赖
MAU_CONFIG_FILE=/private/mau.json npm start
npm run dev:web                        # 先构建 web/ui，Vite 运行在 5173，/_mau 和 /_agent-router 代理到 8790
```

用 `MAU_DEV_BACKEND_URL` 代理到其他服务。

## 部署

```sh
npm run build:web
MAU_WEB_ROOT=web/dist MAU_CONFIG_FILE=/private/mau.json npm start
```

设置 `MAU_WEB_ROOT` 后，`mau-server` 以和接口相同的域名提供控制台，不需要配置跨域。以 `/_` 开头的路径和 `/health` 路由不会返回页面。[Dockerfile](../Dockerfile) 会构建控制台并设置 `MAU_WEB_ROOT=/app/web`。

服务端发布包包含 `web/dist`；安装发布包后，将 `MAU_WEB_ROOT` 指向已安装 Mau 包中的该目录。`npm pack` 会先构建服务端和控制台。

页面的内容安全策略只允许连接同域。唯一允许嵌入的页面是伙伴交给所有者操作的浏览器实时画面。

## 登录（Cloudflare Access）

在 Cloudflare Access 之后，控制台没有登录页，也不保存令牌，登录方式是边缘身份：`mau.json` 配置 `edgeIdentity`（与 Router 的 `edgeIdentity` 同形）后，Router 对每个 `/_mau/v1`、`/_agent-router/v1` 所有者请求和 SSH 升级校验 `Cf-Access-Jwt-Assertion` JWT，并按配置把邮箱（或服务令牌）映射到所有者；从不信任明文邮箱头或 `CF_Authorization` cookie。服务令牌不等于所有者本人登录：除非它在 `serviceTokens` 里写成 `{ "owner": "...", "access": "owner" }`，否则只能读取（`GET`、`HEAD`，不含 SSH 升级），以及在 Router 的网页接口上发聊天消息、打开私聊、标记已读、申请 socket 票据；其余请求（即 `/_mau/v1` 下的全部写操作）返回 `403 owner_sign_in_required`（Mau 自己的接口会附带该接口所需的 `scope`），除非请求在 `Mau-Token` 头里带着同一所有者的访问令牌且其权限范围覆盖该请求。访问令牌由所有者创建（`mau token create`、`POST /_mau/v1/tokens`）：带权限范围（`chat`、`approve`、`manage`），最长 90 天过期，可随时吊销，服务端只保存摘要；它只在已验证的服务令牌请求上生效，本身不是登录，也永远碰不到所有者专属的接口（令牌本身、清空聊天记录、身份绑定），放行的写请求仍需本服务自己的 `Origin`。`"access": "owner"` 仍是不分范围的另一种做法。`GET /_mau/v1/info` 返回 `{ "login": "edge", "logoutUrl": "/cdn-cgi/access/logout" }`。没有配置 `edgeIdentity`（`edge_identity_required`）或没有开启 Router 账本（`ledger_read_required`）时 Mau 拒绝启动；Mau 始终以关闭 Matrix 的方式运行 Router，不配置也不访问任何 Matrix 服务器。

用 [`mau local`](local.md) 在本机启动的服务没有边缘身份：`GET /_mau/v1/info` 返回 `{ "login": "local" }`，控制台用本机所有者令牌登录。`mau local` 输出的 console 地址在片段（`#token=…`）里带着令牌；页面把它存进当前标签页的 `sessionStorage`、立刻从地址里去掉，之后作为 Bearer 头发送（事件 socket 仍走一次性票据，附件走同一个头）。没有令牌的标签页会提示令牌从哪里来；退出登录即丢弃令牌。

- 启动时凭同域 Access cookie 读取 `GET /_mau/v1/account`，由 Cloudflare 附加 JWT。
- 未开通的账号显示整页“此账号未开通 Mau（邮箱）”和“切换账号”（Access 退出）。
- Access 会话过期（接口被重定向、`401` 或套接字重新取票失败）时显示“登录已过期”横幅；“重新登录”把未发送的输入按对话存入 `sessionStorage` 后刷新页面。
- “退出登录”跳转 Access 退出。
- Cloudflare 对跨站请求同样附加 JWT，因此边缘身份的非 GET 请求必须带控制台的 `Origin`（`edgeIdentity.origins`，默认取公开地址的源，或与请求自身 Host 相同），且请求体类型不能是表单可发送的类型。Access 之后的非浏览器调用方（命令行）需带显式 `Origin`。

## 对话

对话来自 Router 的所有者账本（`/_agent-router/v1/web`），控制台按 `GET /web/me` 公布的功能开关工作：没有 `history` 时提示聊天记录不可用，没有 `send` 时对话只读。

- 每个自有伙伴有一个单聊。对话列表常驻在对话旁边（手机上是首页），每行带最后一条消息和未读数；点对话页头的名字或该行的按钮，伙伴资料在列表的位置打开：环境状态与自检、渠道、连接器、文档，以及配置（内核、运行时允许选择时的模型与思考强度、环境方案、销毁环境、删除伙伴）。
- 新建伙伴时填写名称、可选的职责（一行，最多 200 个字符，显示在资料页的名字下方），并选择独立环境或与自己的另一个伙伴共用环境（见 [共用环境](environments.md#partners-sharing-an-environment)）。默认是独立环境；有伙伴拥有自己的、未销毁的环境时才能选择共用。共用环境的伙伴在请求返回时即可使用。它的资料页写明与哪个伙伴共用，没有暂停、恢复、核对和销毁；自检、文档和设置仍是它自己的。拥有环境的伙伴的资料页列出共用它的伙伴；在这些伙伴被删除之前，销毁该环境或删除该伙伴会被拒绝，并指出是哪些伙伴。
- “新建群聊”创建 Router 群聊房间，填写标题并选择最多 20 个自有伙伴。群里只有被所有者 @ 的伙伴（或 `@所有人`/`@all`）开始处理；没有 @ 的消息只记录。成员面板可改名、添加和移除伙伴。
- 消息包含文字和附件（Router 公布该功能时）：图片内嵌显示，其他文件显示为下载卡片。来自其他渠道的消息带渠道标记。
- 发送失败保留草稿，重试复用同一个幂等键。
- Router 提供 `reset` 时，可以“新对话”开始新会话，也可以在设置中清空某个对话的聊天记录。
- 伙伴的指令（`AGENTS.md`，只读）和记忆（`MEMORY.md`，作为一份文档编辑）在对话旁打开。

Host 健康检查不代表消息链路已通过；线上验收必须从控制台发送消息并确认收到伙伴回复。

## 执行过程与交互

控制台通过 Router 的公开运行、事件和调用结果接口读取执行过程，在触发它的消息下方显示增量正文、推理、工具参数与结果、运行状态以及待处理的审批和提问。所有者可以回答审批和提问、停止正在进行的回复，或向它追加文字，全部经过 Router。原生选项和回答格式由 Host 的公开交互转换器决定，Mau 不自定义审批选项。审批回答或结束后不再单独成条：它问的那一步在执行过程里自己写明结果（已拒绝、已取消），获准后执行的就是普通的一步；找不到那一步时，它是执行过程里的一行，点开是所问的命令。

一条回复的各个步骤收在一行里，按类别计数（「已探索 2 个文件 · 已运行 4 条命令 · 询问 reviewer」）。展开后每个步骤一行，写的是做了什么：

- 命令用内核的模型为它写的那句说明当标题（Claude 的 `description`）；没有说明时写它运行了哪些程序（「已运行 git status、git log、head」），不写命令原文。
- 一个步骤算哪一类，先看内核自己怎么说：Codex 对自己命令的解读（读、列、搜），ACP 内核给调用的 `kind` 和 `locations`；都没有时才按命令的第一个词猜。
- 连着读的几个文件并成一行，写出文件名。
- 内核为自己做的事不算步骤：Claude 加载工具定义，以及 Host 已经报告过的产品工具在 Claude 这边的重复记录。

每行只有标题。行尾的箭头展开这一步运行、说了或输出了什么：命令和它的输出、思考过程、伙伴消息的原文，或工具的参数与结果。

断线后按事件游标续读。刷新后从保留的历史重建，事件丢失时明确提示；已结束的运行从 Router 归档读取一次。已处理或过期的交互不可再次提交。伙伴把浏览器交给所有者时，实时画面在对话旁打开。

构建版本检查只在页面闲置时刷新旧页面：有待完成的修改、打开的弹窗或表单、输入框聚焦时不刷新。

## 伙伴协作

伙伴之间用 `partners` 工具招募和发消息（见 [Partners](native-work.md#partners)）。控制台把这些显示在它们所属的对话里。

- **话题。** 别的伙伴派给一个伙伴的每件事，在它自己的一条会话里做，控制台把它显示成这个伙伴页面上的一个话题。开头的那一轮照常显示在对话里它开始的位置。后面又有几轮时，这一轮下面多一行：事情的名字、一共几轮、最新一轮的开头，点它在对话右侧打开话题——开头的那一轮，一条写着回复轮数的横线，然后每一轮是对方问了什么（先显示开头几行，可以展开）和这个伙伴答了什么。后面的几轮不在对话里铺开。话题里有新内容时，这一行上有一个圆点，输入框上方有一行写明是哪个话题，点它直接打开；打开着的话题算已读。话题里的输入框写进的是那条会话：以所有者的原话作为那条会话的一轮，发起话题的伙伴不会被告知。回执丢失后把同样的话再发一次，是同一条消息，不会多跑一轮。话题不会结束：它的会话换到新的上下文继续时，话题里出现一条"新对话"分隔线，照常可以写。页面打开的是最近开始的话题和最近有动静的话题；翻到对话顶部会自动加载更早的消息，然后是更早开始的话题，不需要点按钮，阅读位置不动。话题不管多长，都从第一轮读起。对话列表里一个伙伴只有一行：它的话题里有新内容或正在做事，都显示在这一行上；在对话里搜索也会搜到话题里的内容。
- **消息与结果。** 一个伙伴发给另一个伙伴的消息，是接收方一条会话里的一轮；结果回到发出消息的那个对话。两者都显示成它所触发的那条回复的第一个步骤：一行，前面是对方的小人（「收到 chief 的询问」「收到 reviewer 的回复」），名字点了打开和那个伙伴的对话，行尾的箭头展开对方写的原文。回复合上时的那一行也以它开头，用的是这条回复自己的口吻（「收到 reviewer 的回复 · 已运行 1 条命令 · 询问 reviewer」），事情只有一轮时还写出它的名字（「收到 chief 的询问「计价方案评审」」），所以一个对话读起来只有所有者和这一个伙伴；回复还在执行或没有完成时，这一行同样先写是谁发来的（「收到 helper 的询问 · 处理失败」）。结果不是完整回答时，这一行下面会说明：没有完成、已停止、没有执行、结果未知（控制台认识的原因用一句话说出来），或者回答太长被截短、完整内容在那个伙伴的对话里。没有回复跟着的消息（以通知交回的结果）仍单独显示在对方的小人和名字下面。这些都取自 Mau 随事件记录的 `display`，不从写给模型的文字里读取；没有 `display` 的事件原样显示全文。
- **对话列表**只在最后一条是人或这个对话自己的伙伴写的时候才显示预览；别的伙伴发进来的内容和系统提示不作预览。
- **执行过程里的 `partners` 工具。** 每次调用是一行（查看名单、招募、转达、询问、告知、等待、解散），前面是所提到的伙伴的小人，名字是链接。行尾的箭头展开告诉对方的内容；没有内容的调用展开的是参数与结果。被拒绝的调用用一句话说明原因。
- **审批卡片。** 伙伴的操作需要所有者批准时，卡片出现在发出消息的那个对话里，位于提出请求的伙伴的小人和名字下面。控制台按界面语言，用请求里的各项内容组织卡片文字：谁在请求、在处理谁转来的消息、要执行的操作、连接和参数（参数较长、只显示开头时会注明），两个选项也跟随界面语言。没有这些内容的卡片显示服务端的文字和选项。卡片只能回答一次，之后显示已批准、已拒绝、已过期、已撤回或已在其他地方回答。等待批准的伙伴会在对话列表里标出。
- **已解散的伙伴**不再出现在顶部一行和列表里；伙伴分组末尾有一行可以展开它们，每个都能恢复，按名字搜索也能找到。伙伴资料的配置里可以解散和恢复，这与删除不同：解散后对话和记忆都保留。设置里同样不再列出它：「消息渠道」不显示它的渠道，连接器页面的「使用此连接的伙伴」里也没有它。
- **伙伴资料。** 资料页写明是谁招募了它、它用的是哪个伙伴的环境，点击即可打开那个伙伴的资料。配置里的内核是这个伙伴自己运行的内核（同一个环境里的伙伴可以用不同的内核），模型和思考强度也来自这个内核。
- **电脑上的伙伴。** 新建伙伴的第三个选项是「我的电脑」：伙伴是你电脑上已经装好的 Agent。创建后对话框显示一次配对码和要在电脑上运行的命令。它的资料页用「设备」代替「运行环境」（状态、设备名、平台、内核、最近在线、重新配对、解除配对），没有能力和文档两页，配置页没有模型和销毁环境；对话列表里它的状态是等待配对、在线或离线。见 [连接你电脑上的 Agent](external-agents.md)。
- **新伙伴的内核。** 新建伙伴选择「与伙伴共用」时，如果所选伙伴的环境提供不止一个内核，对话框会让所有者选择新伙伴用哪一个，默认是环境的主内核；只有一个内核时不出现这个选项。环境不提供的内核，或运行时当前在环境里不可用的内核，会被拒绝并用一句话说明。

## 设置

顶部导航的最后一项是账号（手机上在品牌图标旁、列表上方），点开是设置：覆盖在应用上的弹窗，左侧导航：通用（语言、外观、头像）、连接器、消息渠道、身份与配对、扩展、
数据控制（通过 Router 账本清空某个对话的聊天记录）、帮助与法律、退出（边缘登录的登出）。伙伴自己的状态和配置在伙伴资料里。
扩展页列出 Skills、MCP、内核插件、Hooks、Tools 和 CLI，均显示尚未接入：伙伴可以在自己的环境里安装和使用。

页面可直接链接：`#/settings/<分区>[/<项目>]`，例如 `#/settings/connectors/gmail`。跳转 OAuth 授权前控制台记住当前页面，
回调的 `/?view=connectors&oauth=…` 会重新打开它。宽度小于 640 px 时弹窗全屏，导航是第一页，各页面带返回按钮。

界面、字号、间距和组件来自 `@olorinm/agent-ui/app`（设置页用标准密度，执行过程和审批卡片用紧凑密度）。

## 渠道

渠道在「设置 → 消息渠道」中按伙伴连接，流程在弹窗内完成。每两秒查询一次 Router 的连接任务，遇到临时网络错误、服务端错误或限流后继续轮询，并提供重试按钮；任务不存在或已过期时停止轮询。Router 返回的 `qr` 是终端字符画，控制台根据任务里的 `https` 链接自己生成二维码，同时提供打开链接。任务在 Router 内存中保留十分钟，过期或找不到时提示重新开始。飞书个人权限（以主人身份）在「设置 → 连接器 → 飞书」通过 Agent Connectors 授权，见 [connector-accounts.md](connector-accounts.md)。

### 恢复已有飞书应用

飞书连接失败后，点击「恢复连接」，填写开发者后台的原 App ID。控制台会保留已知的
App ID 和区域，通过飞书官方页面重新授权；无需复制 App Secret。
如果凭据已经保存，仅绑定失败，则直接复用凭据。失败任务在 Router 重启后仍可查看。

## 验证

```sh
npm run test:web
```

会构建控制台、运行连接层测试，并用 Chromium 操作测试用 Mau：从 Access 会话打开、新建伙伴、共用环境、暂停与恢复、连接渠道、自检、销毁、设置与连接器、对话、群聊、附件、执行过程与审批、伙伴协作（消息与结果、审批卡片、解散、内核）、切换语言、退出和登录失效。CI 设置 `MAU_WEB_E2E=1`，没有构建产物时直接失败而不是跳过。云端生命周期、Host、Access 和渠道都是测试替身；扫码、真实 Access 登录、渠道授权和模型回复需要在实际部署上验收。
